Aletheia answers one question before an agent spends money: is this token, wallet, transaction or claim safe? It forks the chain and actually executes a buy and a sell, puts the evidence to a multi-model jury, and signs the result — so the answer can be checked without trusting us.

01 / The problem

A token can be safe to buy and impossible to sell.

Every security scanner reads the contract source and reasons about it. That catches clumsy scams. It does not catch a contract that permits your buy and reverts your sell — because nothing in the code has to say that. The logic can be a whitelist, a tax that only triggers above a size, a check on who is calling. Reading intent from code is guessing about behaviour, and an agent acting on that guess loses money on-chain, irreversibly. The usual remedy is a trust score — which asks you to trust the thing you were trying to verify.

04 / Difference

Nothing is true until it's proven.

Three things this does that a similar-sounding service does not.

It executes the trade

Static scanners read and infer. Aletheia measures. A sell-only honeypot passes every code audit and fails here, because the sell actually happens.

The receipt covers the whole answer

Signed over a digest of the full response, never a prefix of it, so verification cannot silently cover less than what you received.

A missing feed is never a bad grade

When our market data is empty the dimension returns no judgement rather than a negative one. A gap in our data is not a finding about the asset.

05 / How it works

The mechanism, in order.

What actually happens between your request and the signed answer.

  1. Gather — On-chain facts from seven independent sources — GoPlus, OKX Onchain OS, DexScreener, honeypot.is, Alchemy RPC, Solana RPC and deployer tracing — cross-checked rather than single-sourced.
  2. Simulate — Fork mainnet at the live block, fund a throwaway account, buy the token, then try to sell it across multiple DEX routers, sizes and origin addresses. A token counts as a honeypot only if it is buyable but unsellable on every route — which is how selective honeypots get caught.
  3. Argue — A diverse multi-model jury reasons over the evidence, one model arguing the bull case and another the bear, until they converge. The verdict records the disagreement, not only the outcome.
  4. Sign — EIP-191 over a digest of the exact bytes returned. Recover the signer offline and compare it against the address published at /.well-known/aletheia-signer.

How it is built

A Hono server behind Caddy, fronted by OKX's official x402 seller SDK. Payment verifies and settles in middleware before any handler runs. Inference walks an ordered chain of models with a concurrency cap, retry-with-backoff on transient errors and a per-call timeout, so a single unavailable model cannot take a paid endpoint down. The fork simulation runs against a live-block mainnet fork.

06 / Who pays

Why anyone buys this.

An agent that trades needs a gate before every trade — not a report someone reads once, but a check invoked on every risky action, priced at cents so it never has to be justified. The manual version of this job (read the contract, check the holders, trace the deployer, judge whether the buzz is real) takes one to two hours, and analysts charge for it. Revenue compounds with an agent's activity rather than arriving as a one-off.

10 / Limits

What this does not do.

Printed here rather than buried.

  • Listing is under review. Approval is OKX's queue, not ours.
  • Zero sales. The marketplace is days old with near-zero volume across every ASP &mdash; the case is argued from the product, not measured from revenue.
  • The fork simulation needs a liquid pool to fill against and falls back to a static read when there is none &mdash; labelled, never faked.
  • Wallet-history coverage varies by chain; each response names which checks actually ran.
